### S3-1 — Player replacement leaves the old actor resources undisposed

**Evidence / symbols:** [PlayerController](../../src/player/PlayerController.ts) `replaceModelRoot` lines 942–974, `remountEquipmentVisuals` 995–1004, `detachEquipmentVisual` 1006–1012, `mountEquipmentVisual` 1025–1063 and `dispose` 1743–1759; [loadGltf](../../src/assets/loadGltf.ts) `disposeObject3D` 217–242.

**Trigger:** changing equipped body outfit or other player model via `applyAppearance` while a skinned outfit and possibly accessory meshes have been rendered. The replacement calls `mixer.stopAllAction()`, `disposeOutfitMaterialClones(oldRoot)`, detaches `oldRoot`, attaches the new root and binds a new mixer; **it never calls `disposePlayerVisual(oldRoot)`**. That helper does the necessary `disposeObject3D` traversal and `Skeleton.dispose()` bone-texture release. Further, `remountEquipmentVisuals` clears the per-slot `attachedEquipmentVisuals` map without first detaching/disposing the previous equipment objects on the discarded root; the new mounting path can no longer find those prior attachments by slot.

**Root cause/consequence:** material-clone cleanup was treated as complete old-model cleanup. The explicit resource-disposal contract for per-clone skeleton textures and accessory resources is skipped; those resources may remain allocated/renderer-managed after root detachment. This proves a cleanup omission, **not** a quantified or necessarily permanent JavaScript heap retention path, because the detached root may be garbage-collectable. The GPU lifetime nevertheless lacks explicit release and repeat swaps can accumulate outstanding resources pending driver/renderer reclamation.

**Minimal corrective approach:** after safely reparenting held items and sockets, dispose the entire superseded player model and its old accessory subtree through the existing object disposer, avoiding disposal of moved children; preserve request-token cancellation and do not dispose loader-shared objects. **Alternative:** centralize appearance-root ownership and explicit accessory-slot release before root replacement; stronger contract, larger refactor. **Verify:** repeat 20+ outfit changes with/without pauldrons and animation; assert old skeleton textures and unique materials receive one dispose event, the active root/equipment remains usable, GLTF cache resources remain intact, and GPU memory reaches a stable plateau. **Confidence:** high in missed cleanup, runtime leak size unmeasured.

### S3-2 — Detached livestock manager teardown misses rendering disposal

**Evidence / symbols:** [SettlementsManager](../../src/settlement/SettlementsManager.ts) `dispose` lines 1829–1845 iterates `detachedLivestock` with only `animal.dispose()` and `animal.mesh.removeFromParent()`. [AnimalAgent](../../src/fauna/AnimalAgent.ts) `dispose` 2026–2044 intentionally cleans life/corpse/labels/animations, **not** root GPU resources. Both [disposeLivestock](../../src/settlement/livestock.ts) 1143–1149 and [createFauna.disposeAgent](../../src/fauna/createFauna.ts) 506–515 explicitly call `disposeObject3D(mesh)` in addition.

**Trigger:** world rebuild/app teardown while player-owned livestock or a travelling merchant pack animal remains detached from a resident settlement.

**Root cause/consequence:** this owner has a third disposal implementation omitting the shared GPU release stage. These agents can have actor-local `Skeleton.boneTexture`, variant-tinted materials and procedural fallback geometry. Scene detachment and registry clear do not emit Three.js dispose events. GPU retention until external/driver reclamation is plausible, not measured.

**Minimal corrective approach:** reuse the established `disposeLivestock` release path for detached animals when their manager is destroyed, respecting registry reclaim/ownership so the same actor is not disposed twice. **Alternative:** a single idempotent animal presentation cleanup primitive used by all owners; more surface area. **Verify:** teardown with a detached mounted horse and active merchant pack animal, plus reclaimed home livestock; listen for one dispose of actor-owned skeleton/material/geometry, none for GLTF-shared, and no duplicate/reanimated ghost. **Confidence:** high.

### S3-3 — Actor materialization has no measured publication budget

**Evidence / symbols:** [SettlementsManager](../../src/settlement/SettlementsManager.ts) `ensureLoaded` 1257–1306 awaits chunks and launches an asynchronous settlement build; `recheck` 1407–1425 can start multiple sites; initial neighbor eager load 1309–1314. [createSettlement](../../src/settlement/createSettlement.ts) `materializeSettlementResident` 1426–1511 calls `NpcAgent.create` then `scene.add(agent.mesh)`; `collectAgentBatch` 585–595, 1514–1516 awaits the concurrent `flatMembers.map` of resident tasks. [assembleCharacter](../../src/characters/assembleCharacter.ts) 49–85, 150–206 creates per-actor bones/skeletons/skinned parts and loads cached assets; [actorCullBounds](../../src/render/actorCullBounds.ts) 70–159 computes skinned bind-pose bounds at construction.

**Trigger:** arriving at a village, eagerly building neighbor settlements, teleport, reload, or concurrent cold/warm GLTF completions. Multiple residents can complete construction and attach to the scene in one interval; a count/time deadline for completed actor CPU publication is not visible on this path. First display subsequently allocates/uploads per-actor bone textures and may submit several skin meshes per actor. Asset-cache hits avoid network and shared geometry allocation but **not** actor assembly, per-actor skeletons, cull setup, appearance materials or first GPU state.

**Consequence:** potential frame-time spikes in actor construction and first-draw GPU activity; analytical scaling with resident count and simultaneous builds, **not a measured hitch**. This extends Session 2's publication-boundary concern to actors without re-auditing terrain. Residency acceptance/rollback already guards stale settlement publication, and `Promise.allSettled` retains rollback ownership; do not replace those safeguards.

**Minimal corrective approach:** first attribute prepare/instantiate/scene-attach/first-render times and counts, and measure peak concurrently pending and completed resident models. If confirmed, coalesce/budget *completed actor presentation publication* at the existing settlement/world lifecycle boundary, with settlement and actor identity validation, rather than adding a parallel scheduler or throttling authoritative simulation. **Alternative:** cap per-settlement assembly concurrency or stage mesh visibility; lower peak CPU but may delay NPC appearance/interactions and complicate rollback. **Verify:** fixed-population home/neighbor cold and warm loads, quick border traversal, simultaneous builds, teleport and rebuild; count model completions, peak CPU ms and GPU uploads per frame, inspect proper cancellation and actor identity. **Confidence:** high for missing publication bound, medium for realized performance impact.

### S3-4 — NPC animation evaluation does not follow view visibility

**Evidence:** [NpcAgent](../../src/ai/NpcAgent.ts) `update` 3239–3263 and 3858–3915 always reaches `syncAnimation` and `anim.update(dt)` for a live ticked agent; the only explicit permanent-dead exception advances the death clip for a bounded period. [agentAnimationSet](../../src/shared/agentAnimationSet.ts) 60–65, 143–149 allocates/updates a per-actor `AnimationMixer` even when clips are absent. [AnimalAgent](../../src/fauna/AnimalAgent.ts) 2686–2739, 3971–3994 runs the mixer in the cadenced presentation tail, whose [policy](../../src/fauna/animalUpdateCadence.ts) 48–56, 95–108, 133–153 uses player distance/importance rather than camera frustum: immediate/full near, up to 20 Hz mid and 10 Hz far before phase spread; important animals remain full rate.

**Trigger/consequence:** turn the camera away from a loaded population or hide it through sight presentation: rendering culling can reduce draws, but resident NPC animation updates and associated transform work still run. Fauna saves presentation work by distance but not by true view state. One-shot combat, mount/lead and corpse presentation are priority exceptions. The costs are CPU mixer evaluation; **GPU skinning/draw cost is separate and only arises on submitted meshes**. The simulation cadence and authoritative world behavior are intentionally not reviewed or to be changed here.

**Minimal approach:** profile mixer counts and CPU time independently of simulation, then consider a bounded, owner-local *presentation-only* cadence for unimportant NPCs if measured. Preserve accumulated animation time, interaction/combat immediacy, blend semantics and initial reappearance pose. **Alternative:** frustum-aware mixer suspension; potentially larger savings but shadow-caster, fast-turn, teleport and offscreen-shot continuity risks. **Confidence:** high for mechanism, medium for benefit.

### S3-5 — LOD policies are shared as a type, not uniformly deployed as model LOD

**Evidence:** [agentPresentationLod](../../src/render/agentPresentationLod.ts) 23–55 picks near ≤18 m, mid ≤36 m and far beyond, with an important override. [agentPresentationVisibility](../../src/render/agentPresentationVisibility.ts) 25–38 hides only registered *optional nodes* and never touches actor root. [NpcAgent](../../src/ai/NpcAgent.ts) 1954–1963 registers only nodes named `ubcHairAttachment` or `ubcBeardAttachment` and applies the policy in `update` 3860–3865. The shipped [assembleCharacter](../../src/characters/assembleCharacter.ts) 49–85, 150–185 adds head/hair/garments as skinned components; this path does not establish general per-distance mesh simplification or additional LOD geometry. [AnimalAgent](../../src/fauna/AnimalAgent.ts) instead uses the independent presentation cadence; player has no population LOD requirement.

**Effect:** no universal actor triangle/skin/material reduction for distant but on-screen NPCs or fauna, and disabling two optional attachments may yield no saving when those named nodes are absent. The policy distinguishes mid/far but the current adapter treats both identically. Hard threshold changes have no dedicated hysteresis; visible optional hair can toggle near 18 m, subject to node availability. This is a limited deliberate guardrail, not proof that expensive meshes render unnecessarily.

**Minimal approach:** instrument actual optional-node availability and per-family submesh/triangle/draw census. Extend the existing owner-local LOD only to demonstrated safe components; never hide body/interactive equipment or change simulation state. **Alternative:** simplified proxy/HLOD or rigid instanced far silhouettes only after GPU census and appearance/interaction constraints establish a need. **Confidence:** high for scope gap; performance significance unmeasured.

### S3-6 — Fauna skinned bounds are not governed by NPC's conservative helper

**Evidence:** [AnimalAgent](../../src/fauna/AnimalAgent.ts) 1872–1915 clones/constructs its visual and optionally invokes `shareActorSkeletons`, but does not call `installActorCullBounds`; NPC explicitly calls both in [NpcAgent](../../src/ai/NpcAgent.ts) 1907–1911. [loadGltf](../../src/assets/loadGltf.ts) 58–66 computes *geometry* bounds on cache root, not an actor-wide animated envelope. [actorCullBounds](../../src/render/actorCullBounds.ts) 41–67 documents why bind-pose spheres do not safely contain every skinned pose and provides conservative fail-open handling. Existing [actorCullBounds.assets.test](../../src/render/actorCullBounds.assets.test.ts) 62–131 samples NPC/legacy poses, not the equivalent fauna integration.

**Risk:** native SkinnedMesh lazy bounds can reflect only an initial pose; unvalidated animation envelopes may clip moving limb/head, corpse or shadow at frustum edges. This is **not a demonstrated popping defect on shipped animals**; the required pose envelope and asset usage have not been evaluated in this review.

**Minimum:** probe shipped wild/livestock GLBs across actual locomotion, attack, grazing, death and variant scale, including light/camera independent frusta. If reproduced or bounds are proved unsafe, reuse the same helper on already-cloned animal visuals and fail open for unsupported transforms; do not invent a parallel fauna-only culler. **Trade-off:** a conservative radius submits extra near-edge skin meshes; unculled fail-open is costlier but correct. **Confidence:** medium.

### S3-7 — Sharing asset buffers does not collapse actor draw calls

**Evidence:** [assembleCharacter](../../src/characters/assembleCharacter.ts) 49–85, 114–138, 150–206 creates skinned body/head/hair/garment components, sometimes new cloth-tinted materials; [npcAppearance](../../src/ai/npcAppearance.ts) 188–279 deterministically varies role outfit, hair, body build, clothing hue and skirts. [ubcOutfitMaterials](../../src/assets/ubcOutfitMaterials.ts) 43–96 clones selected outfit/hair/accessory materials per actor to prevent cache-wide tint mutation. [loadGltf](../../src/assets/loadGltf.ts) 48–101 shares base textures/geometry/clips, but preserves separate rendered parts and instance-bound skeletons. NPC/fauna shadow distance is 36 m ([NpcAgent](../../src/ai/NpcAgent.ts) 518–523; [AnimalAgent](../../src/fauna/AnimalAgent.ts) 425–428; label sync 3891–3915 / 2717–2739).

**Effect:** draw submissions are roughly resident actors × visible submeshes × applicable render passes (with culling and materials changing those factors). Shared GLTF geometry avoids redundant base GPU buffers, but not an individual draw per visible skinned part or bone-palette update. Individual tints/material variants complicate merging and program reuse. The prior review's historical NPC submesh counts are leads, not today's measured census. No evidence supports globally instancing independently animated, equipment-bearing NPCs.

**Minimum:** split CPU mixer work, main-pass draw calls, shadow draw calls, per-material count, shader program families, skinning GPU cost and first-upload bytes with actor-family labels. Compare simple accessory suppression/mesh consolidation against texture atlas/material grouping **only if** bottleneck is confirmed. **Alternatives:** near actors remain independent; rigid attachments/far proxies may batch selectively; skinned instancing requires independent bone palettes and a much more complex animation/update path. **Confidence:** high for multiplicative mechanism, medium for measured importance.

### S3-8 — Skeleton sharing has proven safe limits, not global palette pooling

**Evidence:** [actorSkeletonSharing](../../src/render/actorSkeletonSharing.ts) 26–32, 54–109, 125–158, 160–220 requires identical actor-local Bone objects and compatible inverse binds, remaps weighted skin indices into cache-shared geometry, and leaves incompatible parts separate. It is called on **per-actor clones**, not loader roots. Existing [assets tests](../../src/render/actorSkeletonSharing.assets.test.ts) 163–185, 188–276, 286–314 exercise exact vertex parity, actor independence, cache geometry and skeleton disposal. In those test fixtures, assembled female kits end at one palette and male kits at two because the male head is incompatible; shipped multi-part fauna test fixtures collapse to one. These are **source test expectations, not newly executed test results**.

**Implication:** sound actor-local deduplication with intentional fail-open; there is no cross-actor skeleton sharing (which would compromise independent animation), and palette count is not always one. [actorCullBounds](../../src/render/actorCullBounds.ts) 70–159 runs after skeleton sharing for NPCs and installs per-mesh bounds without geometry mutation. Future garment attachments, new children, body morphs and equipment modifications must not assume automatic rebind/cull-envelope refresh. **Approach:** preserve tests/flags `?actorSkeletons=0` for A/B, add changed-model regression fixtures when actual rig changes land. Do not pursue shared global bones or unsafe skin-index reassignment. **Confidence:** high.

## 5. LOD, animation and CPU/GPU cost separation

**Rendering LOD:** optional-node visibility for NPCs, native frustum culling for bounded NPC skinned parts, native/fallback fauna culling and distance-based shadow-casting; **none is a simulation scheduler**. Rapid camera rotation, combat, mount/lead and teleport require pose-on-reentry, no incorrectly hidden interactable body and intact off-camera shadow casters. The current bound radius is heuristic: a passing static fixture is not a proof for every future clip. Earlier bounds review 029 identified transform edge cases; the current helper checks invertibility, finite matrices and similarity transforms before enabling culling. Do not reassert already-addressed edge cases as current defects.

**CPU animation:** one `AnimationMixer` and resolved actions per live character (including empty fallback animation sets); NPC alive tick advances every time it is called, fauna uses accumulated `dt` through its presentation gate. Incompatible heads retain extra skeletons. **GPU skinning:** applied to actually submitted skinned meshes, with one or more actor-local bone palettes. **Draw calls/materials/shadows:** additive, not reduced simply by sharing a palette; shadows are separately submitted where actor cast distance and light frustum permit. **Creation:** GLTF clone + skeleton rebind + skinned bounds scan + materials/labels on main thread. **GPU upload:** first mesh/material/bone texture use can occur later than `scene.add`. **Authoritative simulation:** separate ownership; no optimization recommendation here removes a simulation tick or animal/NPC population.

## 6. Resource lifetime, model work and cross-system risks

The URL-keyed GLTF cache and `remappedByGeometry` cache intentionally retain shared immutable geometry/attributes/materials/clips for the app lifetime. A retained shared resource is **not a leak merely because it survives actor stream-out**. Actor-local skeleton textures, custom materials and procedural geometries are different: they require explicit owner cleanup. Normal resident NPC, resident livestock and wild-fauna exits implement that split; live player swaps and detached livestock final cleanup do not. Repeated actor creation also retains application-lifetime *asset variants*, which should be characterized by URL and remap key rather than misclassified as per-actor leaks.

Recent outfits influence system 16 specifically through [npcAppearance](../../src/ai/npcAppearance.ts) 188–279: female fallback to supported bodies, profession outfits, work skirts, NPC age/body scaling, and color choices affect component counts, materials and possible skinned animation envelopes. [Player visuals](../../src/player/playerVisualPreset.ts) and [player equipment visuals](../../src/player/playerEquipmentVisual.ts) define separate live-swap and skinned accessory paths. This **does not** verify wardrobe appearance quality, all children's geometry, clipping or unimplemented armor scope. The [character system 17](./SYSTEM-REVIEW-MATRIX.md) remains separately partial. Livestock/mount visual owners cross into systems 06/12/15; animation/performance instrumentation into 27. Their gameplay correctness is not accepted by this review.

## 7. Alternatives and decisions

| **Merge/instance all characters or proxy at distance** | Potential submission reduction | Per-actor animation, morphs, outfits, identity, hit feedback and shadows make global instancing high-risk | **Not recommended without measurement** |

No change to deterministic AI, resident counts, persistence, gameplay behavior, renderer platform (vanilla Three.js/WebGL2), material fidelity or Stylized Realism is justified by the static review.

## 8. Required measurements and targeted verification

1. **Lifecycle correctness (highest confidence, no GPU benchmark required first):** unit/integration disposal-event spies on `Skeleton.boneTexture`, per-actor material and procedural geometry for player model swaps (including accessories), detached merchant mount/player horse teardown, and reclaimed livestock; verify loader-shared resources remain un-disposed and reference maps empty.
2. **Actor census:** main/shadow/mirror calls, triangles, skinned-mesh count, skeletons per actor, material identities, first texture/program uploads, optional-node availability and per-family actor count for NPC, wild fauna, livestock, player. Differentiate in-frustum, back-facing and occluded/concealed actors.
3. **CPU timeline:** measure async asset-clone completion, `assembleCharacter` per stage, skeleton rebind/remap, `installActorCullBounds` vertex scans, scene attachment, NPC/fauna mixer-update cost and total actor presentation CPU separately from simulation.
4. **GPU real device:** Intel Arc Windows (and representative weaker WebGL2 adapter if available), controlled cold/warm scene, static/turnaround and first-render frames; do not infer GPU upload time from scene-add timers. Track `renderer.info` deltas plus appropriately scoped GPU timing/driver counters where available.
5. **Scene transitions:** small/large populated settlement, eager neighbor build, edge oscillation, rapid traversal, teleport, rebuild and repeated hide/show; ensure finished async actor work never publishes into disposed settlement and authoritative NPC IDs are unchanged.
6. **Animation correctness:** male/female/child proportions, profession outfit/skirts, rigid hats and skinned hair, mounts/juveniles/variants; walk/run/work/combat/lying/death with camera and shadow frusta at image edges; repeat with `?actorSkeletons=0` and current flag. Check head/garments and raycasting at altered scale.
7. **LOD perceptual checks:** threshold crossing and rapid backtracking around 18/36 m; important actor overrides; no hairstyle pop where visible or wrong equipment disappearances; distance cadence reappearance interpolation and correct combat timing.
