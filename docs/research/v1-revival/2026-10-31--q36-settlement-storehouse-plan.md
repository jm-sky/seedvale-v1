## 2. Design

### 2.1 Decided by Opus (author delegated: model use, size, NPC entry, anchors)

1. **Every settlement** — `OUTPOST`, `SM`, `MD`, `LG`, `XL` — gets exactly one storehouse (author req. 1; the home settlement is SM and hosts the rat quest). No config switch to turn it off per size. The crate-only path survives **only** as the defensive fallback when HouseBuilder assets fail to load (props catalog fallback), never as a planned outcome.
2. **Model — one reference point.** `STOREHOUSE_DEFINITION` (id `storehouse-6x4`) in `assets/houseDefinitionExample.ts`, the only place naming the storehouse model: the existing 6×4 timber-frame cottage shell (`COTTAGE_6X4_C`: `KIT_WOODGRID`, same roof) via `plasterHouse(...)` with **one front door in the centre module, no windows, no chimney, no `furniture`, no `lamp`**; `label: 'Magazyn'`, examine `'Wspólny magazyn osady — bez okien, z szerokimi drzwiami.'`. Not in any home pool (`pickHouseDefinition` can never return it); `houseDefinitionById` resolves it. 6×4 everywhere, also in OUTPOST/SM — the interior must stay spacious (req. 4); a smaller shell would not leave free floor.
3. **NPCs do not enter** (req. 7 delegated). Deliveries and pickups happen at an **outdoor loading bay**, so the door is never a logistics bottleneck (req. 6) and closure can never block logistics (req. 5):
   - `STOREHOUSE_BAY_SLOTS = 3` slot points along the storehouse's **long side wall** (not the door wall), 1.0 m out from the wall, 1.6 m apart, door-local fixed offsets → stored in plan data (`plot.storehouse.baySlots`, world XZ), pure and Three.js-free;
   - each NPC resolves its slot by a stable hash of its **NPC id** (`slot = hash(npcId) % 3`) — concurrent deliverers spread over three points; no queueing system is added;
   - `landmarks.settlementStorage` = bay slot 0 (player interactable, offscreen/manager delivery, legacy single-point consumers) — keeps every F2 consumer valid without change; `landmarks.settlementStorageSlots: Vector3[]` added; `resolveNpcSettlementStorage(storage, kind, npcId?)` picks the slot for food when slots exist (wood unchanged → stockpile);
   - the bay is the **permanent** delivery/collection point, so it *is* the external fallback of req. 5: a future closure (none exists today, F9) must only gate the door/interior, never the bay. Goods stay in `SettlementEconomy` throughout — no second ledger, nothing moved between ledgers, so no duplication/loss on closure, reopening or in-flight orders (an order heading to the bay still completes at the bay).
4. **Storage is split inside/outside, distributed** (req. 2, 3): food is represented **inside** (derived visual from `SettlementEconomy` food stock, `storageVisuals` mechanism, placed along the back/side walls only, max footprint ~1 m deep, leaving the centre ≥ 4 × 2 m free — req. 4); wood stays at the existing stockpile plot wherever the planner put it (not moved next to the storehouse); the existing `crate.glb` becomes one bay-side crate (outdoor dressing, next to slot 2, not on a slot). No static barrel/sack filling of the interior.
5. **Door works for the player**: the storehouse assembly is passed to `createHouseDoorController` together with the house assemblies (separate list concatenation — never into `houseAssemblies`), and its disc is added to the door-sound tracker input. The player can enter and see the food inside; repair interaction stays at the bay/wall (`settlementStorage` interactable).
6. **Plan data.** Plot `plot-infra-storehouse-0` (`role: 'infrastructure'`, id helper `storehousePlotId()` in `villagePlan.ts`), planned **right after the stockpiles**, in `utility ?? publicZone`, preferred ring like the stockpile (`footprintRadius × 0.12…0.3`), **not** forced next to the stockpile. Radius `STOREHOUSE_PLOT_RADIUS` = disc covering shell + bay apron (≈ `houseFootprintRadius` 4.06 + 1.5 ≈ 5.6 m). `houseDefinitionId`, `houseYaw` (door faces the plaza, no jitter) and `storehouse: { baySlots }` on the plot. Building `building-storehouse-0` (`role: 'utility'`), landmark kind `'storehouse'`, local path to the plot.
7. **Never dropped.** The storehouse is mandatory now. If `pickPlot` reaches `finalFallback` for it, extend its search (more rings, like the Q34 house fallback) rather than overlapping or dropping; census metric "storehouse final fallback" must be 0 on the sampled seeds, else stop (queue §3, settlement scale question).
8. **Terrain pad** `ClearingLayout.storehouses: readonly ClearingArea[]` (one entry) — consumers per F7; separate from family-aligned arrays.
9. **Never a house.** Not in `landmarks.houses/homes`, `houseAssemblies`, `ClearingLayout.houses`, lodging, house interactables, house lights, chest instancing. Own `landmarks.storehouse` (position, yaw, definitionId, label, examine, footprintRadius, assembly — load-lifetime). Colliders via `buildAssemblyCollidersWorld` in `registerSettlementColliders`.

## 3. Implementation steps (Q43, Sonnet)

1. `STOREHOUSE_DEFINITION` + tests (one front door, no windows/furniture/lamp, never returned by `pickHouseDefinition` for all sizes × 200 indices).
2. `villagePlan.ts`: `storehousePlotId()`, landmark kind, `VillagePlot.storehouse?: { baySlots }`. `householdYard.ts`-style pure helper (`storehouseLayout.ts`) for bay slots + interior free rectangle from definition + yaw. `villagePlanner.ts`: plot, building, landmark, path, bounded extra-ring search (2.1.7).
3. `villageClearing.ts` pad + `regional`; `roadNetwork.ts` clearings; worldgen cache validator; `props.ts:566` reject list.
4. `props.ts`: build/batch the shell, `landmarks.storehouse`, `settlementStorage` = slot 0, `settlementStorageSlots`, interior food visual (walls only), bay crate. `createSettlement.ts`: colliders, door controller list, door-sound disc. `npcResidentAnchors.ts` / `npcProfessionWork.ts` / `npcLogistics.ts`: slot by NPC id for food.
5. Census (extend `scripts/perf/census-house-yards.ts`): storehouses per size (must equal settlement count), final-fallback count (0), storehouse ∩ any plot/compound (0), bay slot inside a collider/plot (0), interior free rectangle unobstructed, storehouse ↔ stockpile distance p50/p90 (informational). Seeds 42, 415424794 (+1, 2, 3). Record in §5.
6. Tests: planner — every size × SEEDS has exactly one storehouse, no overlaps, door faces plaza, family count/ids unchanged, determinism cold/warm cache; anchors — three distinct bay slots outside all colliders, NPC slot choice stable per id and spread across slots for a sample of ids; storage destination / NPC delivery / offscreen delivery / storage repair tests green; `landmarks.houses.length === families.length`.
7. Caches: `settlement-definitions` 6 → 7, `chunk-tiles` 7 → 8, `road-routes` (bump), `abandoned-cemeteries` (bump, F7), `caves-v2` only if it reads plan/clearings (check, record). `WORLDGEN_EPOCH` stays 1.
8. Verification: `npx tsc --noEmit`, targeted vitest (`src/settlement`, `src/ai` storage/delivery, `src/world` transport, `src/terrain` cemetery/cache), `pnpm run lint:fix`. Then STATE settlement storage section, Q29 row, §5 notes, queue Q43 status, queue §2 visual check entry.

**Not in Q43:** rats inside the storehouse (author (a), later quest follow-up), a dedicated storehouse model, a closure mechanic, fences (Q35), other placement (Q37), moving wood storage, economy quantities.

## 4. Acceptance and stop conditions

- **Done when:** every settlement (all sizes) on seeds 42 and 415424794 (rings ≤ 5) has one storehouse, 0 final fallbacks, 0 overlaps; NPC food delivery/pickup use the three bay slots, offscreen delivery and player storage/repair use slot 0 (tests); households unchanged; caches bumped; census recorded; author visual check queued (§2): storehouse reads as storage (windowless, bay with crate), door opens for the player, interior free floor with food along the walls, NPCs deliver at the side bay, not at the door.
- **Stop if:** the storehouse looks like a home in the author's check (→ dedicated model / more dressing, author); it cannot be placed without final fallback (→ settlement scale, author); a bay slot is unreachable; any other plot kind's final-fallback count rises.
- **Performance:** +1 building per settlement through the existing static batch (0–few new buckets + 1 door leaf per pass), +~10 colliders, interior food visual bounded like the current crate visual, no lights, no per-frame work beyond one more door in the existing controller. Record draws per settlement (structural), no FPS claim.
