## 2. Verified instrument → collect → aggregate → export chain

1. `src/main.ts` reads `?benchmark=<id>` and boots `BENCHMARK_FIXTURE`; `src/app/createApp.ts` creates the runner, auto-runs it, and publishes `window.__seedvaleRunBenchmark`, `__seedvalePerfLastReport` and `__seedvalePerfReports`. `benchmarkFixture.ts` fixes seed=42, day=0, time=07:00, terrain resolution=193, loadRadius=3, version `tools-001-v1`. `benchmarkScenarios.ts`: `current`, `forest`, `settlement`, `settlement-heavy`, `water`, `night`, `stress`, `stream`. `current` is non-canonical. Heavy settlement uses a bounded seeded mountain-settlement selection and fails explicitly.
2. `src/perf/benchmark.ts` selects an anchor, **forces High**, preloads required chunks, sleeps 1000 ms, resets agent/grass totals, then collects a 30-second `monitor` session (default). Stream moves +X at 14.4 m/s every 100 ms by elapsed wall time. There is **no cold-start measurement mode**, no canonical camera rotation/agent-heavy/meadow route, and no frame-time/weather freeze throughout the measured window. Fixed fixture starting time does not equal an immutable clock through 30 seconds. Investigate positioning/camera framing and resident population in the capture; `forest` is not a guaranteed meadow.
3. `src/app/gameLoop.ts` measures `simulateMs` and `renderMs` with `performance.now`, calls `renderer.info.reset()`, mirror pass, optionally shadow refresh, composer and label renderer. Its `renderer.info.render.calls/triangles` at end and mirror checkpoint feed `monitor.endFrame`. Validate actual frame accounting against installed Three; **total is not a per-pass/per-bucket split**. `withCategory` category spans feed `PerfMonitor` (`SHADOWS` / `POSTPROCESS` reserved but not populated separately); `RENDER` is CPU-side wall clock including possible driver stalls, *not pure CPU rendering*. No stand-alone frame update/render p95/p99 exported.
4. `src/perf/monitor.ts` holds a rolling 300-frame live p50/p95/p99 and collects a full-session `frameMs[]` plus `renderCategoryMs[]`, sums of category times/calls/triangles, 8ms labelled hitches and max 24 long-frame records (≥80ms). `endSession()` returns those in memory. `src/perf/report.ts` converts to `PerfReportJson`: FPS avg/min/p1, frame avg/p95/max, aggregate renderer calls/tris, systems averages, hitches, at most five worst long-frame samples, context, scene estimate, optional agent/grass/isolation. **Full-session frame p50/p99 and the raw series are dropped at this edge**, not inherently missing from collection. FPS avg is reciprocal of mean reported frame duration, not necessarily presented-frame throughput under browser scheduling.
5. `src/perf/sceneCensus.ts` traverses currently visible ancestors only, estimates one-pass draws/tris by name/userData, including agent asset-family and near/mid/far detail and skinned mesh counts. Camera relevance is **agent-root point-in-frustum**; it is not mesh-envelope culling, occlusion, camera-layer filtering, actual shader/material groups, shadow refresh, or WebGL submissions. `Math.max(1, instance.count)` can count zero-count instances as one; arbitrary multi-material groups are approximated. `settlementShadowCasters` contains useful tags but is **shadow-eligible content, not actual shadow draws**. It does not give settlement static/dynamic main-pass attribution.
6. `src/perf/isolationProbe.ts` runs post-session sequential hide-visibility/feature-off probes (150ms settle, 400ms sample, 150ms GPU drain). They are **different short windows**, not matched paired per-pass tracing. The changed scene/device state can have variance/first-use effects. Isolation deltas are *exposed costs*, not recoverable improvements; do not add A+B+C savings. `gpuTimer.ts` uses `EXT_disjoint_timer_query_webgl2` for a non-nested `TIME_ELAPSED_EXT` around `postProcessing.render()+labelRenderer.render()` only; it excludes mirror, and never times shadow separately. `available=false` or zero resolved samples yields no GPU data, but `PerfReportJson` does not distinguish unsupported/no-results/disjoint/skipped. Reset clears samples, **not in-flight queries**, so probe-edge sample provenance is not guaranteed. It silently discards disjoint batches and caps 8 pending without exported dropped counts.
7. `src/perf/agentCpuDiag.ts` records manager NPC subspans (crowd, agents, livestock, rats, social, streaming, maintenance, remainder) and fauna/livestock behavior, life/presentation, cadence, queries. `buildAgentCpuReport` exports averages/cumulatives; these are **not** mixer-only NPC cost, skinned render work or GPU. The livestock duplicate update counter requires canonical identity validation (September review); do not label it a runtime bug from this counter.
8. `src/perf/grassFinalizationDiag.ts` times main-thread grass chunk mesh build, attributes, bounds, LOD, attachment, plus optional Chrome `performance.memory` deltas and per-species generated buckets. It is **events during the measurement only**, not active/visible/actually submitted instances at capture, not worker placement, no upload-bytes/ranges or pool high-water. `src/terrain/chunkManager.ts` uses worker-generated placements, rebuild/dispose, hysteresis, and `src/terrain/grass.ts` uses InstancedMesh draw-range/filler/geometry LOD; legacy has no V3 tiled pool/upload tracking. Do not show speculative V3 backend counters in a V1 baseline.
9. `src/perf/programCensus.ts` records program counts, first-use/cache-key/material/asset approximations and stage wall-clock upper bounds. Enabled by `?programCensus=1` and default on stream; entire app lifetime, **not an isolated measured window**. Detailed events are available through `window.__seedvaleProgramCensus` / console and formatted Markdown, but are **not in `PerfReportJson`**. This does not measure per-program shader compile/link time.
10. `benchmark.ts` formats `getBenchmarkReport()` into a Markdown string, exposes `window.__getBenchmarkReport` / `__copyBenchmarkReport` and logs report objects. Neither JSON nor Markdown is written to disk automatically. The human/browser agent must save both. The Markdown currently repeats the Agent CPU block: `formatReport(report)` already appends it and `getBenchmarkReport` appends it again. The 2026-09-21 `029/030/031` reports are **dated Markdown snapshots** (no matching latest raw JSON committed), not current results. Raw JSON in `results/` is from early September. There is no git SHA, browser/GPU/driver/OS, camera pose, power/thermal state, run ID or cold/warm marker in the formal report. Device DPR (`pixelRatio`), viewport, preset, fixture seed/weather/season are present; viewport is `window.innerWidth/innerHeight` (not necessarily drawing buffer pixels).

**Important:** `SHADOWS` and `POSTPROCESS` CPU categories being empty is not evidence of zero pass cost. Actual `renderer.info` aggregate is not disjoint across passes unless validated. A scene-census draw estimate may greatly exceed on-screen `renderer.info` calls.

## 4. Minimal fixes and STOP gates

**P0 shared foundation, one writer for A0a+B0:** (1) extend existing `types.ts`/`monitor.ts`/`report.ts`/`benchmark.ts` with session distributions and bounded raw sidecar; (2) capture required environment/SHA/phase/camera/population metadata with explicit unavailable values; (3) actual *observed* main/shadow/mirror pass submission counts, per-frame plus actor/settlement bucket with residual. Validate renderer and grouping semantics against controlled fixtures and `renderer.info`; do **not** rename `census` fields to actual. Use only opt-in instrumentation and restore hooks on normal end, error, reload/dispose; no second profiler, no engine/Three patch if avoidable. (4) GPU timer explicit availability and sampling provenance; GPU unavailable **does not** block CPU/render-call baseline, but blocks GPU-only claims. (5) JSON + raw + Markdown artifacts with provenance, no silent clipboard/manual-only dependency. (6) settle/runnable scene readiness and zero-frame/empty populations/excessively different resident scene rejection. (7) C0: minimal *current V1* grass active/LOD/flower/placement/finalization/stream/upload-allocation baseline counters without a V3 pool implementation.

**P0 STOP (per lane):** no verified target device/browser or commit SHA; failed build/tests; missing raw/report pair, fixture mismatch or unknown frame count; wrong scenario/anchor/camera/population; non-validated combined calls passed off as per-pass; A/B without real pass attribution; C without credible active grass/flower and stream/finalization measurements; materially unstable/unrepeatable warm-run workloads. Save partial artifacts under *UNVERIFIED* with reasons, do not calculate claimed gains and do not begin optimizations. GPU timer unavailable/disjoint alone is **not** STOP if explicitly marked and other evidence exists. A failed heavy-settlement selector is STOP for B, never silently substitute `settlement`.

**P1 once baseline gate passes, only for chosen mechanism:** A: native animated bounds/cull sample and NPC mixer-only timing before cadence changes. B: per-class material/primitive and settlement create/rebuild/upload/dispose counters before another batching family. C: actual bytes/ranges/pool occupancy/capacity and texture/attribute lifetime before retaining a V3-style pool; worker placement latency and short cold-fill/travel traces. Compare sidecar/counters with actual browser/GL behavior; measure instrumentation overhead/disabled path. Do not build all P1 before choosing a single implementation slice. **P2:** GC attribution, detailed per-program compile/link diagnostic (without fake timings), multi-camera shadow/mirror trace, long soak.

| Stream + cold | `stream` seeded route; fresh context load separately, then explicitly warmed run on same build/device | chunk attach/dispose, program first-use, stalls, grass fill and memory drift. Do not call the existing 1s post-preload warmup a cold run. |
| Water control | `water` (and matched `no-reflections` isolation) | mirror/reflection bias, pass totals; no extra scenario. |
| Sanity/control | `settlement` only if needed; `current` is noncanonical; `night`/`stress` optional targeted visual regression | avoid multiplying benchmark variants before one coherent baseline. |

Use one reference machine (author's Intel Arc laptop) and real hardware WebGL; headless SwiftShader measurements cannot certify laptop frame performance. One browser tab/process with an active SeedVale scene at a time. Capture ≥3 sequential warmed repetitions where feasible, variance, actual scene state and any throttling. Use same run duration/settings/poses in paired versions. For each run store JSON, bounded raw samples/sidecar, human-readable Markdown, metadata and optional trace/screenshot; preserve run/source SHA and any anomalies. Compare same phase *only*, no sum of `hide-X` differences, and no inference of GPU milliseconds from CPU wall time.

## 6. Order and acceptance

1. Cursor **P0 instrument/export only**; tests and static build; no optimization. One shared A0a+B0 pass collector.
2. Verify on actual browser/hardware that P0 is trustworthy, including abort/dispose, shadow refresh cadence, mirror skip, thin/empty/zero-instance cases, GPU timer unsupported and JSON round-trip.
3. Record warmed `settlement-heavy` rotation / agent face, `forest` grass-rich face, `stream`, and `water` control; separately cold/first-use. Stop per failed lane rather than replacing data with scene estimates.
4. Review whether A, B or C still dominates at matched workload; only then select bounded P1 diagnostic for chosen optimization. A first, B second, C third is provisional roadmap order, not proven ROI.
5. No runtime optimization, V3 migration, shadow/LOD/cadence change, visual reduction, or simultaneous multi-track intervention in this readiness slice.
