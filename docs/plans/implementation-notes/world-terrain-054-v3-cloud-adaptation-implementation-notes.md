## Concrete implementation contract (no architectural choice left)

**Files to edit:** `src/world/clouds.ts`, `src/world/createSky.ts`, `src/app/gameLoop.ts`, `src/app/createApp.ts` and targeted tests `src/world/clouds.test.ts` and new `src/world/createSky.test.ts`. Do not edit `renderStack.ts`, `weather.ts`, `weatherVisuals.ts`, `dayNight.ts`, `waterMirror.ts`, `groundFog.ts`, `weatherParticles.ts`, `src/render/*`, save files or donor V3.

**The type boundary:**
- In `clouds.ts` export `cloudAppearanceFor(weather,elev)` unchanged, `cloudNoiseData(n=256)` as a testable pure helper, and `attachCloudsToSky(material: ShaderMaterial)` returning `{ update(dt: number, weather: WeatherState, elev: number, enabled: boolean): void; dispose(): void }`. This object is a *material attachment*, not a scene renderer. Put the shader fragments, noise texture and their owned uniforms here.
- In `createSky.ts` call `attachCloudsToSky(sky.material)` once immediately after creating/configuring the Sky; add `WorldSky.updateClouds(dt: number, weather: WeatherState, elev: number): void`, delegating `enabled = isSystemEnabled('weather')`. Preserve `setParams`, `applySun`, `addTo` and the existing `scene.background=null`. In `dispose` dispose the attachment texture first, then Sky geometry/material. Add concise JSDoc (`@domain world-terrain`) for public APIs.
- In `gameLoop.ts` replace only `clouds.update(dt, climate.weather, cachedSky.elev, playerX, playerZ, climate.season)` with `sky.updateClouds(dt, climate.weather, cachedSky.elev)` and remove its `CloudSystem` import/dependency. Do this **after** `tickClimate`/`cachedSky` resolution. `createApp.ts` removes all five cloud-specific references (import, construction/add, dependency, teardown) and retains `sky.dispose()`.
- Keep no `Sprite`, `Group`, PNG loader or `cloudCategoryWeightsFor` in the production cloud path. Remove/replace tests that asserted obsolete light/dense category selection, but **do not delete weather/tint/coverage tests**.

**Shader composition:**
1. Reuse the pre-existing Sky `ShaderMaterial`, not `onBeforeCompile` or a second `ShaderMaterial`. Inject the cloud uniform declarations and helper function before the shader's unique `void main() {`. Inject a statement that assigns `texColor = ...` immediately **before** the unique `gl_FragColor = vec4( texColor, 1.0 );`. Throw clearly in development/tests if either exact anchor is absent or occurs more than once (Three addon change), rather than silently falling back. No vertex shader edit: Sky already has `vWorldPosition` and computes `direction = normalize(vWorldPosition - cameraPosition)` in its fragment.
2. Name new uniforms with a non-colliding `uSvCloud` prefix: `uSvCloudNoise`, `uSvCloudCover`, `uSvCloudTint`, `uSvCloudOpacity`, `uSvCloudOffset`, `uSvCloudEnabled`. Keep built-in `sky.material.uniforms.cloudCoverage.value = 0`; do not bind to `cloudCoverage`, `time` or `sunPosition` of the addon.
3. Noise sampling: only if `direction.y > 0.0` and enabled; `uv = direction.xz / (direction.y + 0.06)`; sample noise at `uv * 0.11 + offset` (R), `uv * 0.37 + offset * 1.7` (G); `n = 0.75*r + 0.25*g`; `edge = 1.0 - clamp(cover, 0.0, 1.0)`; `mask = smoothstep(edge - 0.08, edge + 0.18, n) * smoothstep(0.0, 0.12, direction.y)`; `texColor = mix(texColor, uSvCloudTint, mask * clamp(uSvCloudOpacity, 0, 1))`. This is the decided single-pass variant. Do **not** import V3's baseline cover remap, cloudy sun-colour multiplication, V3 background gradient or V3 sun disc. Existing Sky already computes solar disc/scattering in `texColor`; cloud opacity consequently occludes it without an additional sun glow.
4. Three r185 Sky uses its own `#include <tonemapping_fragment>` and `#include <colorspace_fragment>` **after** `gl_FragColor`. The injected math operates on existing linear `texColor`, and `THREE.Color.setHex(appearance.tint)` supplies a linear cloud tint for the uniform. Never include colour-space chunks twice or copy V3's `toneMapped:false` and final sRGB dither. Keep Sky `fog=false`, back face, geometry scale and default layer/render order unchanged.
5. Texture: copy donor `cloudNoiseData` tileable LCG/lattice loop, use `DataTexture(..., 256,256, RGBAFormat)`, `RepeatWrapping` on S/T, `LinearFilter` magnification, `LinearMipmapLinearFilter` minification, `generateMipmaps=true`, `needsUpdate=true`. Leave `NoColorSpace` for *noise data*, distinct from former colour PNGs using `SRGBColorSpace`. Never share this texture with `loadTexture`'s cache. Avoid CPU noise regeneration per frame, texture allocation per update, or multi-frame shader recompilation.
6. Presentation state: first `update` writes the full weather cover directly to the current cover (avoids boot-time false clear view). Later updates use `shownCover += (target - shownCover) * min(1, clamp(dt,0,0.05)/3)`; clamp target to 0..1, clamp opacity likewise. Drift offset as donor `(0.0026,0.0012) * (1+shownCover*0.5) * clampedDt`. Each update writes tint **immediately**, without double-smoothing V1 day/night/fog. `enabled=false` writes zero effective opacity (not a new cloud reset or weather state), while the current target/easing can continue. Drifting is presentation-only, deliberately not world/persistence deterministic.
7. Controller `dispose` idempotently calls only `noiseTexture.dispose()` and ceases further updates; no need for async callbacks. Sky `dispose` releases geometry/material exactly once. A `rebuildWorldBundle()` does **not** release/recreate either; app teardown does. On context restore allow Three's existing texture reupload path. Do not install separate GPU callbacks. An in-session new game via `rebuildWorld(true)` preserves the same app-owned Sky and reuses its presentation state; next weather update retargets it.
8. Weather mapping stays `cloudAppearanceFor`; in particular fog is cloud-sparse while separate `groundFog.update` handles local fog. Storm/rain cover floors hold even for forced weak intensity. Weather/season are not persisted by cloud code. Loss of old per-category season morphs is intentionally recorded in the plan; do not simulate fake PNG categories from procedural noise.

## Stop-and-report conditions

Stop the affected stage and report evidence (do not choose a different architecture silently) if:
1. `Sky` in the actual installed Three version no longer contains the verified `direction`/`texColor` variables or the unique output anchor, so injection cannot preserve the current scattering/colour pipeline.
2. The Sky material is replaced by a non-`ShaderMaterial`/node-material pipeline or the new GLSL cannot compile in the actual browser despite the supported r185 source after a focused fix.
3. An existing sky/cloud/reflective scene owner was changed concurrently so the same shader is not authoritative, or removing `CloudSystem` would remove a non-cloud capability.
4. There is a reproducible resource leak or material GPU regression that cannot be fixed **within** the cloud shader/texture boundary.
5. A requested fix would require modifying V1's weather, fog distances, lighting, render passes, saves, day-night semantics or simulation. Log the conflict and ask for scope approval instead.
