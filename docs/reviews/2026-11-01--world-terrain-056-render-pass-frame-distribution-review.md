# Critical review — world-terrain-056: render-pass frame distribution and map quality

**Date:** 2026-11-01  
**Scope:** review of [world-terrain-056](../plans/world-terrain-056-render-pass-frame-distribution-and-map-quality.md), current V1 main (inspection around `c0d63a0`), historical Windows Arc/WSL benchmarks.  
**Method:** static inspection of repository files and existing benchmark reports; **no new runtime capture, visual test, GPU pass timing, or performance measurement**.  
**Decision:** **APPROVE STAGE A WITH CHANGES; DO NOT PRE-APPROVE A GENERIC SCHEDULER, CADENCE CHANGE, OR RESOLUTION INCREASE.**

## Executive assessment

The plan is technically well scoped (non-authoritative presentation only, reversible experiments, visual gates, respect for world-terrain-055), but the principal promise — improved p95/p99 through distributing passes — is **hypothetical, not established**. Its most promising *incremental* opportunity is reducing sun-shadow refresh while the player/forward-shifted camera frustum is moving; the already-enabled actor-only half-rate shadow change cannot be counted as a future gain. Second is avoiding unnecessary mirror work when **no sampled water is relevant to the visible view**, followed by narrowly targeted mirror/shadow collision avoidance. Avoid blanket cadence on screen-space postprocessing.

The plan is broad (XL) for a question that may be resolved by **two owners plus a small arbitration rule**. Stage A is essential; Stage B should be conditional, and an abstraction decision should follow actual co-occurrence traces. Record p95/p99 separately from throughput; a flatter distribution can produce no p95 gain, and stream hitches can dominate p99 regardless.

### Critical findings (severity / minimal correction)

1. **HIGH — No per-pass GPU time or definitive overlap trace.** [gpuTimer.ts](../../src/perf/gpuTimer.ts) is bracketed around the beauty/postprocessing render in gameLoop, **after** the mirror; it is not a shadow-only or mirror-only GPU timer. [passSubmissionCollector.ts](../../src/perf/passSubmissionCollector.ts) counts actual calls/triangles in mirror, shadow and main, **not pass GPU duration**. Existing “no-shadows/no-reflections” probes expose **non-additive total render wall-time** (driver waits, changed shaders and scene submission), not standalone GPU costs. **Change:** Stage A must capture per-frame executed-pass flags, CPU wall spans, overlaps, refresh gap and context/visibility, and label isolated GPU samples separately; use bounded diagnostics, never blocking per-frame query readback.
2. **HIGH — Frame staggering does not mathematically guarantee p95/p99.** Two passes each on half the frames can overlap on 25% of frames. Moving them apart may reduce the largest combined peaks but raise the fraction of moderately heavy frames; p95 can remain unchanged or worsen. If the shadow executes in ≥5% of frames, its standalone cost still enters p95. **Change:** test overlap and conditional tail distributions (shadow-only, mirror-only, both, neither), report p50/p95/p99 by frame type and full frame, retain only if measured tails do not regress.
3. **HIGH — Walking/turning shadow cadence must be a bounded *temporal* compromise.** A tight forward frustum changes centre on camera yaw; player movement and turning make the current threshold too sensitive. **Change:** trial a frame-aware minimum 1 skipped frame / soft 20–30 Hz shadow budget under ordinary movement, with hard fast-turn/teleport/visibility/stream-in validity escape, max age in **milliseconds plus frames**, and a displacement/angle threshold measured **since last actual draw**. Begin with **alternating refresh under motion**, not all-pass scheduler. At 30–35 FPS every-other-frame equals only ~15–17.5 Hz: visual tests must accept this, not assume it imperceptible.
4. **MEDIUM — Visibility model must respect the actual consumers.** Mirror skip cannot use player distance or just ocean visibility; multiple chunk-water materials sample the same RT, and a static ocean plane is a distant fill. Shadows cast by off-camera objects may fall into the view, particularly at low sun; do not cull shadow casters by main-camera frustum alone. **Change:** conservative camera-frustum intersection of *visible reflective water surfaces* (incl. chunk water; river reflection only if it samples the RT), cached/bounded broad-phase; safe fail-open around transitions. Retain Three.js culling, layer filters, actor distances, frustum fit and point-light budget rather than duplicating them.
5. **MEDIUM — Timing/ownership hazards are underspecified.** Mirror runs **before** this frame's shadow refresh, so it can sample the prior valid sun shadow map; a reordered shadow refresh could change reflection appearance. First shadow render is forced before mirror is allowed; `noteShadowRefresh(shadowWanted)` currently describes the budget decision, not the extra missing-map force. The mirror sets `lastRenderSec` / `renderedLastCall` **before** checking whether its camera is below the water plane, so “wanted” is not the same as “actually drawn”. **Change:** preserve ordering and shared matrix snapshot, track **actual successful** execution, handle skips/disposal/context restore/rebuild/quality resize, exception-safe WebGL render-state restoration, and avoid a coordinator recording unexecuted jobs as completed.
6. **MEDIUM — Map artifacts have not been visually attributed.** 512 is a selectable **Low** sun shadow quality, not evidence that a current High screenshot uses it. 128 is a reflection RT and may produce blocky/blurred water, but its contribution is deliberately attenuated by [waterMaterial.ts](../../src/world/waterMaterial.ts) (up to ≈18%, usually ≈1–2%). Also check shadow acne/bias, PCF, temporal lag, texel snapping, AO half-res upsampling, shoreline height/floor/body textures (per-chunk terrain resolution, e.g. 193), DPR and TAA-free screen-space aliasing. **Change:** require reproducible screenshots, effective live RT dimensions and an A/B that changes **one** cause at a time. A screenshot is not available for this review, so the actual cause is **unverified**.

### Expensive work not to misclassify as schedulable render passes

- **First-use shader/program linking** on newly streamed content: native [CA2/stream analysis](../performance/results/2026-10-30--win-q5-ca2-ab.md) attributes ~200–400 ms WATER frames to first-use mirror rendering and a 37–128 ms synchronous river-tile build. These affect p99/max and **will not be solved by alternating shadows and mirrors**; prewarm / worker-prefetch owners already exist, some flag-gated.
- **CPU matrix, actor and settlement submission:** [Q14](../performance/results/2026-10-29--win-q14-frame-matrix-once-ab.md) already eliminated redundant matrices; [Oct 31 settlement diagnosis](../performance/results/2026-10-31--wsl-settlement-diagnosis.md) finds settlement:decor 78 main / 183 shadow / 44 mirror, skinning/material switches and ~6.3 ms settlement and actor render isolation each. Batching is independent of cadence (not an automatic 056 task). [pointLightBudget.ts](../../src/world/pointLightBudget.ts) is already bounded each frame.
- **Non-render CPU spikes:** chunk streaming, vegetation/grass builds, river work and simulation scheduling can dominate tails. Never delay authoritative simulation or collision to meet the graphical pass budget. Avoid duplicate visibility traversals and allocations.
- **AO transparency-aware full-scene redraws:** currently disabled by default in configuration, after a separate measured improvement. Do not count this historical gain again.

## Forecast: INCREMENTAL uplift over current mechanisms (not new measurements)

Assumptions: original preset, resolution and scene content unchanged; a **moving/turning** player unless noted; shadow frequency reduces from near-100% to roughly 50–67% only where it is currently not actor-only throttled; existing mirror runs ~30 Hz at high FPS and ~every other frame under low FPS. Small, low-cost view rejection; no new AO temporal caching, no effect-content omission, no major shader/program hitch fix. Large/small percentages are scene and hardware dependent; all below are **plausible engineering envelopes, not confidence intervals or measured current FPS**. “FPS +” is computed illustratively against the dated FPS anchors above using `1000 / (1000 / F_anchor − saved_ms)`, **not against current measured FPS**.

For the **stationary settlement Q51 fixture**, much of the obvious half-rate shadow gain is **already present**; do not apply the moving-settlement row there. The expected incremental static gain from mere phasing is likely small (often **0 ms**) unless measurements show real overlapping expensive updates. The optimistic envelopes require a visually accepted aggressive cadence and demonstrate a GPU/CPU critical-path saving; a **negative** gain is possible.

### Map-quality trade-off (excluded from gross forecast above)

| Change | Pixel/memory scaling (nominal) | Performance sensitivity and decision |
| --- | --- | --- |
| Shadow **512→1024** (Low only) | 4× shadow texels, 2× linear density | Existing High already 1024. May improve low-quality edges, but extra GPU shadow raster/bandwidth is unmeasured. Profile independently; do not apply to all presets. |
| Shadow **1024→2048** (experimental; requires bypassing existing clamp) | 4× shadow texels, 2× linear density | Large potential GPU/memory cost, same CPU object-submission count, additional memory bandwidth. Could erase cadence savings; only after visual evidence that PCF, bias, crop and stability cannot fix artifact. |
| Water mirror **128→256** | 4× RT texels (16,384→65,536), 2× linear detail; plus depth target | CPU scene traversal/draw count likely similar, but GPU fill and bandwidth rise. Water shader attenuates reflection strongly; require side-by-side visible benefit and measured effect, not automatic upgrade. |
| AO half-res→full-res / DPR increase | ~4× sampled pixels per doubled linear dimension (effect dependent) | **Not a shadow/map quality cure**. Postprocessing full-screen cost may rise each frame; keep independent of cadence A/B. |

**Sensitivity example only, NOT a measurement:** if a higher-resolution shadow RT adds 1 ms of GPU critical-path cost on each updated shadow frame and it refreshes on 50% of frames, the extra average GPU work is ~0.5 ms/frame; subtract that from the saved-time estimates **only if GPU/driver contention makes it critical-path work**. A 2 ms per-refresh increase would consume ~1 ms/frame; at lower frame rates or cache misses, p95 could worsen. There is no credible measured bound for 2048 or 256 on current V1, so the table above assumes **unchanged map sizes**.

## ROI-ranked required changes to the plan

1. **Highest ROI / minimal scope — Stage A pass-coincidence trace + one shadow-motion A/B.** Record actual executed shadow/mirror booleans, reason (moving/actor/stale/force), elapsed since success, shadow-centre displacement, FPS, scene state, per-frame CPU wall and available nonblocking GPU spans; report conditional p95/p99 and interval histogram. Trial half-rate under ordinary movement with fast-turn override and capped age. Pair with visual walking/rotation/low-sun; revert if artifacts or tails worsen. **Do not retest Q51 static as if new.**
2. **High ROI / cheap guard — mirror relevance before expensive pass.** Reuse current water visibility/chunk metadata; conservative camera-frustum broad-phase for all surfaces sampling the shared RT. Log skipped-by-visibility, draw calls, misses at shoreline/rotation/teleport. No scene traversal just to decide skip; no omission of NPC/object reflection content without D8/D13 approval.
3. **Medium ROI / gated — deterministic shadow-vs-mirror collision policy.** Only if trace proves both overlap materially. Start with **one conditional rule**: if the optional mirror refresh is due and shadow refresh is also due, defer the lower-priority one by one frame **only while max age + visual validity allow**. Account for mirror-before-beauty order and initial shadow map. Compare one-pass vs coordinator A/B; do not promote to generic scheduler unless multiple independently expensive deferrable passes remain.
4. **Medium/low ROI — render-target artifact diagnosis before map changes.** Side-by-side 512/1024 shadow, 128/256 mirror, filtering/bias/normal bias, texel snapping, AO half-res, DPR and per-chunk water data. Keep original preset baseline and record *net* time including extra texture cost; no global 2048 default.
5. **Low/negative ROI for 056 — cadence of AO/SMAA/bloom and heavyweight visibility framework.** Explicitly classify screen-space passes as per-frame/correctness-dependent unless a separate temporal reconstruction experiment is justified. Do not build global scheduler, shadow static/dynamic layer cache, or duplicate Three.js culling just to satisfy “not every frame”.

## Scheduler verdict and required verification gates

**No shared scheduler now.** The world has **one** independently cadenced water mirror, **one** shadow budget, conditional god rays, existing light/LOD filters, and no evidence of enough interchangeable deferrable render jobs to justify global scheduling. A small optional arbiter near gameLoop can coordinate decisions **without owning their cadence state**. It should receive due/forced/visible/last-executed and return admit/defer with max staleness, rather than reimplementing each owner's clocks. Advance each owner only on a confirmed draw. Preserve one matrix snapshot, render-target/autoUpdate restoration and lighting consistency. No simulation authority or NPC identity changes.

Before moving beyond stage A:
- Capture a **current-SHA native Windows Arc** baseline and matched A/B for **moving settlement-heavy**, static settlement, forest, water, ordinary roaming; same camera route/quality/viewport/seed/weather, ≥3 repetitions per arm, population and compilation warm-up controlled. WSL can screen changes separately, but never mix it with Windows deltas.
- Record overlap percentage, actual CPU/GPU pass times with known timing bounds, p50/p95/p99/max and long-frame attribution, **not only mean FPS**. Test alternate schedules that can reveal worse tails.
- Explicit visual checks: continuous walking, standing NPC shadows, slow and fast yaw, low sun/long external casters, water edge, reflections, visibility transitions, shadow resize, teleport, streaming, pause/rebuild/context restore. User approval for perceptible compromises.
- Profile map quality at unchanged and higher resolution, with separately reported FPS and p95/p99 **net of the quality cost**. Compare preset and live resize behavior; 2048 currently clamps.
- Update the plan's A/B gates with an explicit **stop condition**: if overlap is rare, frame tails are dominated by other jobs, or a one-rule arbiter has no measurable benefit, close 056 without a scheduler.

**Disposition:** request the above clarifications in the plan before implementation. This review makes **no runtime changes** and makes **no claim of new FPS, visual or performance verification**.
