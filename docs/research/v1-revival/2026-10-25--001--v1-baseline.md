## 1. Executive summary

V1 is a substantial playable-world implementation, not merely a terrain prototype. Source code exposes procedural terrain/river and village generation, streamed 3D presentation, NPC and animal agent runtimes, persistent households/settlement economies, physical-resource production and transport, equipment and survival, combat against fauna, contextual/ authored/world-driven quests, local reputation, maps, sound, and versioned saves. A broad unit-test suite and repeatable benchmark fixtures exist. **This is evidence of implementation depth, not proof of current build health, visual fidelity, or enjoyable gameplay.**

The strongest foundation candidates are interconnected systems: deterministic geography and world identity; terrain/river/road/cave shared spatial queries; distinct authoritative household, NPC, fauna, economy, and resource owners; the WorldBundle reconstruction boundary; and world-driven quest/reputation integrations. Some highly visible experiences (landscape, settlements, water, animation, sound) are valuable *preservation hypotheses* until the author confirms them by observing the game.

Main uncertainties are (a) browser/gameplay quality and cross-system behavior at the recorded snapshot, (b) detailed↔off-screen state continuity, (c) render and main-thread cost in dense settlements, (d) lifecycle/persistence edge cases, and (e) the exact product breadth implied by “crafting,” “trade,” “combat,” or “living world.” Existing September audits already narrow many of these; do not start their recon from zero.

**Method and verification boundary.** Inspected repository guidance, indices, architecture/state documents, prior audits, selected actual source modules, and representative test assertions; indexed the committed tree (4,402 entries; 670 `src/**/*.test.ts(x)` files). Source inspection confirms implementation surfaces and some local invariants; **no fresh `pnpm test`, type-check, build, browser playtest, visual assessment, GPU benchmark, or trace was run**. The “implemented and independently verified” class is consequently **unassigned by this R1 pass**. September benchmark numbers below are *existing recorded evidence*, not new measurements.

### Clarifying partial versus absent features

- **Implemented:** physical inter-settlement shipments and merchant journeys; blacksmith production and custom orders; quests observing real world sources; fauna cave habitat; mobile touch controls. Do not call them absent because an umbrella feature is incomplete.
- **Explicitly partial/not implemented:** a general player crafting interface, player-caused NPC combat damage, complete NPC social places/group conversations, full settlement trade market, ordinary wildlife individual save continuity, multiplayer, spherical world, and LLM-generated quests. This distinction follows [STATE](../../STATE.md), [player](../../state/player-systems.md), [combat](../../state/combat.md), and source inspection.
- **Unknown without live inspection:** perceived “V1 atmosphere,” terrain composition, house scaling, model animation quality, weather readability, world narrative coherence, and actual end-to-end performance on target hardware.

## 4. Architectural baseline

### 4.1 Runtime boundaries and ownership

```text
src/main.ts (Start Screen / seed / restore)
   → src/app/createApp.ts (composition + late-bound integrations)
     ├─ app-lifetime player, time, inventory/equipment, quests, reputation
     ├─ app-lifetime Three.js render stack, UI, sound, input
     ├─ src/app/worldBundle.ts (stable outward object, replaceable contents)
     │    ├─ ChunkManager: terrain, rivers, bridge/water/ground queries, chunk workers
     │    ├─ SettlementsManager: settlement records, NPC states, households, economies
     │    ├─ Fauna + spawners: wild fauna / habitat agents
     │    ├─ Caves, resources, world drops and player-built objects
     │    └─ World-owned transport/logistics/knowledge registries
     ├─ src/app/gameLoop.ts (simulation, player interactions, presentation coordination)
     └─ src/app/saveState.ts → persistence/saveData.ts → saveDb.ts
```

This diagram describes conceptual ownership, not a strict dependency rule. `NpcAgent` and `AnimalAgent` are sizable Three.js-aware controllers that combine behavior and presentation; their breadth is **not itself an established defect**. Their state authority must be distinguished from scene-object lifetime. `src/simulation/` provides reusable action/decision contracts rather than one universal simulation scheduler. Source: [architecture](../../architecture/ARCHITECTURE.md), `src/app/createApp.ts`, `worldBundle.ts`, `gameLoop.ts`, `src/settlement/npcState.ts`.

### 4.2 World generation, stream boundaries and geometry

Deterministic world facts are calculated from seed, location and world time; chunk meshes/GLBs are **presentation**, not authoritative world existence. The terrain shaping pipeline is settlement regional smoothing → roads/clearings → river carve. River hydrology uses self-contained D8 river tiles; road crossing records explicitly decide ford versus bridge, and player/NPC/fauna traversal samples the same resulting ground layer. Caves similarly use a retained heightfield as the single spatial authority for floor/ceiling/occupancy/wall resolution, while their meshes and opening cutouts are streamed. Relevant entries: `src/terrain/chunkHeightmap.ts`, `riverNetwork.ts`, `src/settlement/roadNetwork.ts`, `src/terrain/roadBridge.ts`, `src/world/createCaves.ts`.

Terrain streaming and settlement streaming have distinct residency thresholds (documented settlement load/unload 300/420); distance to player selects simulation *detail*, not whether the authoritative settlement exists. Ordinary wildlife is reconstructed from deterministic population conditions instead of persistent individual state; declared persistent cave-habitat occupants and livestock are special cases. Rendering culling/LOD must not be interpreted as simulation gating. See [architecture](../../architecture/ARCHITECTURE.md) and [Sep-21 agent review](../../reviews/2026-09-21--agent-performance-and-simulation-boundary-followups.md).

### 4.3 Time, off-screen agents and production

`src/world/dayNight.ts` owns elapsed world days; weather/tree/crop stages can be derived lazily from time. Per-frame agent `dt` and short real-time player actions are deliberately different timescales ([architecture time model](../../architecture/ARCHITECTURE.md#time-model)). `NpcStateRegistry` persists personal states and travel checkpoints. Detailed NPC decisions and locomotive execution live in `NpcAgent`; off-screen travel, crop catch-up and some transport can advance without rendered agents. `TransportOrder` records **a commitment**, not cargo; real goods live in origin inventory → `NpcAuthoritativeState.transportCargo` → destination. Recipe commits are atomic through `executeProduction`; there is no independent all-purpose production manager. Source: `src/ai/npcTravel.ts`, `src/world/transportOrder.ts`, `src/world/transportOffscreen.ts`, `src/economy/productionExecutor.ts`, `src/settlement/npcState.ts`.

Fauna uses a shared `AnimalAgent` for wild/domestic categories, an importance-aware cadence, and a derived `faunaProximity` runtime index. Ground/water queries are injected from the environment. Individual wild continuity is a documented tradeoff; movement-target randomness can be unseeded ([fauna state](../../state/fauna.md)). The long-term vision of completely independent, persistent individual lives is **not fully proven by existing code**.

### 4.4 Rendering integration, expensive work, caches

Visible Three.js objects, animations, labels, sound, input and composite rendering remain main-thread concerns. Tile/mesh-data/grass/world-knowledge pure computations use the existing worker pool. Chunk mesh/grass finishing still touches the main thread; per-frame finalization budgeting reduces but cannot logically eliminate all spikes. An in-session geometry LRU and a separately versioned disposable IndexedDB worldgen cache accelerate reconstruction; **neither is authoritative saved gameplay**. Region-batched vegetation and agent presentation LOD already exist; do not assume “not yet optimized.” See `src/terrain/chunkWorkerPool.ts`, `chunkManager.ts`, `chunkMeshCache.ts`, `src/terrain/vegetationRegionBatcher.ts`, `src/render/agentPresentationLod.ts`, [performance](../../performance/README.md).

### 4.5 Save, reload, in-session rebuild

The save schema is a serialization boundary, not a runtime store: each domain creates and owns live state; `buildSaveData()` gathers snapshots, validates/migrates them through `saveData.ts`, and stores slots in IndexedDB. Restore constructs owners from saved fields. A same-session `WorldBundle` rebuild carries domain snapshots into newly constructed world systems; the outward bundle identity stays stable and the app rebonds retained player dependencies. Rebuild outcomes are `published`, `stale`, or `failed`, with a runtime validity gate in the game loop. This architecture is deliberate; risks arise at exceptional failure, stale references, and *which* data is persisted—not because bundles are mutable. See [architecture](../../architecture/ARCHITECTURE.md#world-lifecycle), [persistence state](../../state/persistence.md), and [Sep-21 lifecycle review](../../reviews/2026-09-21--player-world-lifecycle-followups.md).

## 6. Weaknesses, risks, and evidence quality

### 6.1 Confirmed scope gaps or code/documented behavior

1. **Player attacks do not hit NPCs.** The shared combat primitives exist, but player melee/ranged target resolution is limited to animals. See `src/player/playerMelee.ts`, `src/player/playerRanged.ts`, [combat](../../state/combat.md) and [STATE §Not implemented](../../STATE.md#not-implemented--intentionally-deferred).
2. **Save ≠ exact persistent world snapshot.** Ordinary wild-fauna individuals, NPC transient action/path/combat execution and some temporary carried NPC items are not saved. In particular [NPC state](../../state/npc.md#limitations) documents material loss if a claim/delivery episode is interrupted after extraction; [persistence state](../../state/persistence.md) classifies this explicitly.
3. **Mounted livestock reference ambiguity:** `SavePlayer.mountedAnimalId` remains an unqualified ID while canonical travelling livestock uses settlement-qualified `PersistentLivestockRef`. Ambiguity can occur when different settlements reuse IDs; recorded in [persistence state](../../state/persistence.md#known-persistence-limitations).
4. **Crafting/tool/combat breadth is narrower than labels suggest.** Player crafting is not a general self-contained loop; blacksmith production/orders exist. General tool wear, full weapon repair/breakage, visible projectiles, player-vs-NPC combat and mounted combat remain absent/partial ([STATE](../../STATE.md), [combat](../../state/combat.md)).
5. **Fauna damage asymmetry:** animal *outgoing* damage uses a species table and does not invoke shared critical/defense stages, unlike other incoming-damage paths. This is a **documented design/implementation difference**, not proven gameplay defect ([fauna](../../state/fauna.md), [combat](../../state/combat.md)).
6. **Loaded tree stage visual lag:** authoritative tree growth is lazy and time-consistent, but already-loaded tree/crop meshes may not visually update for a newly derived stage until mutation or chunk reload ([terrain state](../../state/terrain-and-world-generation.md)). This is a known presentation gap, not loss of underlying state.
7. **UI migration incomplete:** Vue plus remaining vanilla DOM are both supported; legacy prompt-text parsing remains in `src/interaction/interactionView.ts::parseLegacyPrompt`. This raises change-drift risk, but a [Sep-21 review](../../reviews/2026-09-21--quest-ui-interaction-followups.md) did **not** find a current regression on the audited path.

| Stream | 43.2 | 23.1 / 36.5 / 98.5 ms | 12.2 / 2.0 / 1.4 / 2.5 ms |
| Settlement-heavy | 22.2 | 45.0 / 65.6 / 114.3 ms | 25.7 / 4.7 / 1.6 / 4.1 ms |
