- `src/items/armorItemInstances.ts`: `effectiveInstanceWeight` currently quality-scales armor only; use a compatible extension for utility instances. Armor tuning `masterwork` already has weight scale 0.8 but its protection/penalties do not apply.
- `src/persistence/saveData.ts`: player `SaveItemInstance` snapshots and dropped-item `SaveDroppedItem.instance`. Also audit all NPC/merchant/household/container/ground paths using `InventoryContentsSnapshot`, not just player save.

## Design decisions / edge cases to resolve during implementation

1. **Mixed storage:** ordinary shovel/pickaxe/blanket/torch/pan may exist in count form and masterwork in instance form. Existing `isInstanceBackedKind` is a kind-level switch; blindly adding all five kinds to it may break old counted inventory/save and purchases. Choose and test a compatibility strategy rather than a broad eager conversion. Functions `Inventory.has`/`holdsAny`, `HeldTool.equip` and trade count selection need a unified view where appropriate; never duplicate or reinterpret a single physical unit.
2. **Typed quality:** utility quality should be a narrow `common | masterwork` contract and validate eligible `kind`. Avoid accidental `good`/`poor` utility acceptance from legacy armor serialization. `cloneItemInstance` must preserve the quality marker in **every relevant subtype**, including tent and axe weapon instances; ordering of type guards matters.
3. **Identity for held vs carried:** `HeldTool` has `heldInstanceId`; portable torch may use separate player-torch state. Inspect its actual owner before coding. Pan and blanket are non-held; select deterministic concrete source, don't give an upgrade to every item of that kind or passively apply a carried masterwork pan when the grate supplies capacity.
4. **Quality cannot disappear while deployed:** tent's world record must carry identity/quality through wear, save, rebuild and pack. Validate callbacks that construct packed `TentItemInstance` from world state. Weather wear uses lazy time accumulation; halve cumulative damage for masterwork without changing update timestamps or allowing infinite regen. Repair restores condition but not quality.
5. **Torch needs real ownership:** portable `wooden_torch` can currently be a count-based item. Identify where its remaining fuel/time is tracked, and persist the correct masterwork burn state if torch persistence is currently supported. No standing-torch modifier.
6. **Pricing & stock:** don't use `PREMIUM_MERCHANT_KINDS` (kind-level list) to represent the sole utility masterwork stock unless the generated physical instance is actually materialized. Existing armor quality is instance-based; source scarcity should be seeded by stable settlement/trader/site IDs, not wall clock, shop-open RNG or UI render. Count-backed trade paths cannot communicate quality without explicit instance IDs.
7. **Reward reachability:** don't promise an arbitrary quest grants an instance until the current reward application API and persistence are inspected. If this reward payload supports only `ItemKind` counts, extend the existing reward path or gate that slice on a specific compatibility change, never silently deliver a common variant.
8. **Durability semantics:** shovel/pickaxe remain without wear. Blanket/pan/portable torch remain without generic HP; torch only has burn-time. Axe may already degrade in combat but **tree chopping should not be assumed to wear axe** without proving the path. Masterwork endurance covers relevant existing wear; document any unimplemented tree-wear path rather than fabricating tests.

## Verification matrix

- Ordinary-only legacy save loads intact, including count-backed objects, armor and weapons.
- Two same-`kind` utility items (one ordinary, one masterwork) have stable IDs, correct weight, explicit choice, correct purchase/resale, no double-consumption and no duplication through drops/containers/NPC stock.
- Ground action time comparison with same Strength: baseline `T`, masterwork `T/1.5`; no benefit from simply carrying a second masterwork tool.
- Axe has unchanged combat damage and sharpness rules; existing maintenance wear reduced only for actual masterwork instance; no shovel/pickaxe durability.
- Tent pack/place/repair/save/reload retains quality and 2× weather endurance; rest caps and survival/bedroll interactions correct; ordinary unchanged.
- Blanket improves rest only when a masterwork instance is the bedding source; quality explanation truthful.
- Portable wood torch burn lasts 1.5× without changing standing torch or consuming another instance.
- Pan speeds cooking only when that pan supplies the effective two-capacity cooking path; grate always keeps 4 and no bonus; ordinary remains unchanged.
- Trade/loot/reward deterministic for repeated world seed, one-shot persisted, sufficient but not guaranteed availability across sampled worlds. Price/buyback consistent.
- Browser inspection for real interaction times, merchant UI, selected item identity, tent and light behavior. Static tests alone are not gameplay evidence.
