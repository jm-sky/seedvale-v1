## 2. Design (decided by Opus — routine technical choices within the approved epoch scope)

**Principle:** the storehouse is a new **infrastructure plot + building**, never a household house. Simulation keeps reading the single `landmarks.settlementStorage` point; only its value moves to the storehouse door.

1. **Which settlements.** `MD`, `LG`, `XL` get one storehouse (`infrastructure.storehouses: 1`); `SM` and `OUTPOST` keep today's crate (`0`). Rationale: hamlets with 1–3 families do not need a communal building and their plaza is small. One config value per size — the author can change it without code changes (§5 Q36 check).
2. **Model — one reference point.** New `STOREHOUSE_DEFINITION` (id `storehouse-6x4`) in `assets/houseDefinitionExample.ts`, the **only** place naming the storehouse model. It reuses the existing 6×4 timber-frame cottage shell (`COTTAGE_6X4_C`: `KIT_WOODGRID`, same `capRoofWithGables` roof) via `plasterHouse(...)` with:
   - openings: **one door, front, centre module** (`moduleIndex: 1`), **no windows** — the windowless timber wall is the main "not a home" cue;
   - no chimney decoration, **no `furniture`**, no `lamp` (no bed, no chest, no light);
   - `label: 'Magazyn'`, `examine: 'Wspólny magazyn osady — bez okien, z szerokimi drzwiami. Tu trafiają zapasy żywności.'`.
   It is **not** added to `COTTAGE_DEFINITIONS` / `HOUSE_DEFINITIONS` / `HOME_HOUSE_DEFINITIONS`, so `pickHouseDefinition` can never give it to a family; `houseDefinitionById` may resolve it (plan data stores the id). A later dedicated model replaces this one constant (or swaps it for a GLB path in the same owner).
3. **Plan data.** New plot `plot-infra-storehouse-0` (`role: 'infrastructure'`), planned **right after the stockpiles** (Q29 order), in `utility ?? publicZone`, local mode around stockpile 0: `attractor = stockpile plot`, `minAttractorDistance = INFRA_PLOT_RADIUS + STOREHOUSE_PLOT_RADIUS + 0.5`, `maxAttractorDistance = min + 6`. `STOREHOUSE_PLOT_RADIUS = houseFootprintRadius(STOREHOUSE_DEFINITION) + 1.0` (front apron for the service point; 6×4 → 4.06 + 1.0 ≈ 5.1 m). The plot carries `houseDefinitionId = STOREHOUSE_DEFINITION.id` and `houseYaw` = **door facing the plaza centre** (same convention as houses: `atan2` outward + π, no jitter). `buildingsAndLandmarksFromPlots` emits building `building-storehouse-0` (`role: 'utility'`, `footprint = houseFootprintRadius`) and a landmark of new kind `'storehouse'` (index 0). Add the plot to the "important" local-path list (`path-plot-plot-infra-storehouse-0`).
4. **No overlapping storehouse.** If `pickPlot` returns `finalFallback` for the storehouse, drop the plot (settlement keeps the crate, F1 path) instead of overlapping — the storehouse is new optional dressing, not a mandatory object. The census (step 3.5) counts dropped storehouses; it **must be 0** on seeds 42 and 415424794 or the slice stops (queue §3).
5. **Terrain pad.** `ClearingLayout.storehouses: readonly ClearingArea[]` (0 or 1 entry; radius = `STOREHOUSE_PLOT_RADIUS × 0.9`, `targetH` via `averageHeight` + `dryClearingHeight` like houses). Consumers: `roadNetwork.ts` clearings (house height strength), `props.ts:566` vegetation reject, `regional` target average, `settlementWorldgenCache.ts` validator (array required). Separate array — `houses`/`yards` stay family-aligned.
6. **Presentation (`props.ts`).** When the plan has a storehouse plot and the HouseBuilder context loaded:
   - `buildHouse(STOREHOUSE_DEFINITION, builderReady)`, yaw/placement exactly as houses (`placeOnGround`), ingested into the **same** `staticBatch` before `commit()`; **not** pushed to `houseAssemblies`, `landmarks.houses/homes`, `houseLights`, chest placements;
   - `landmarks.storehouse = { position, yaw, definitionId, label, examine, footprintRadius, assembly }` (new optional field; assembly is load-lifetime, used only for colliders);
   - **service point** = door entrance point (assembly `interactionPoints` kind `'entrance'`/`'door'`, to world) pushed **1.2 m outward** along the door normal → `landmarks.settlementStorage` (so F2 consumers retarget automatically);
   - the existing settlement `crate.glb` moves beside the door (door-local `+1.6 m` sideways, `0.9 m` in front of the wall) and `createFoodStorageVisual` is centred on that crate — food overflow stays **outside** (Q29), never on the service point; the two stockpile clutter barrels stay at the stockpile;
   - if the HouseBuilder context failed (catalog fallback path), or there is no storehouse plot: today's crate path unchanged.
7. **Colliders and door.** `createSettlement.ts` `registerSettlementColliders` adds `buildAssemblyCollidersWorld(landmarks.storehouse.assembly)`. The storehouse assembly is **not** passed to `createHouseDoorController` → door stays closed, no interior access (storehouse interior is out of the batch, Q29 rule 5). NPCs and the player use the service point outside the door.
8. **Rats / repair.** No change: nest stays behind a residential house (quest flow and `ratNestPlacement` identity unchanged); repair/inspection already run through the `settlementStorage` interactable, which now sits at the storehouse door, so "the storehouse wall" copy finally matches a real building.
9. **Shadow/census tagging.** Tag the storehouse root (before batching) with the settlement shadow kind used for houses so `sceneCensus` buckets stay meaningful; record draws per settlement before/after (structural only).

**Rejected alternatives:** (a) storehouse as an extra entry in `landmarks.houses` — breaks family index alignment (F3) and would give it lodging/repair/house-interaction semantics; (b) an unmodified home definition — indistinguishable from a home (queue stop condition), with a bed and lamp; (c) moving wood delivery into the storehouse — changes NPC logistics semantics, not asked.

## 4. Acceptance and stop conditions

- **Done when:** every MD/LG/XL settlement on seeds 42 and 415424794 (rings ≤ 5) has one storehouse with 0 drops and 0 overlaps; SM/OUTPOST unchanged (crate); `landmarks.settlementStorage` is the storehouse service point and NPC food delivery/pickup, the player storage interaction and storage repair work against it (tests); households/houses/lodging unchanged; caches bumped; census before/after recorded; author visual check queued (§2).
- **Stop if:** the storehouse cannot be told apart from a home in the author's check (queue Q36 stop condition → dedicated model or more dressing, author choice); storehouses are dropped on the sampled seeds (placement needs a larger footprint → author, it changes settlement scale); the service point is unreachable for NPCs; adding the plot drops or moves a mandatory object into the final fallback (count final-fallback plots of all kinds before/after — must not rise).
- **Performance:** +1 building per MD+ settlement through the existing static batch (expected 0–few new buckets per settlement + 1 door leaf draw per pass, +~10 colliders), no lights, no per-frame work. Record draws per settlement (structural), no FPS claim.
