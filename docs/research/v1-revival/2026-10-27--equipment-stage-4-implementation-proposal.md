## Global compatibility and verification contract

1. **Source fidelity:** unchanged 87 V3 records/metadata; no mutation of `src/items/v3Equipment/catalogue.ts` definitions, source fixtures or pin; use independent Stage 3 fidelity/test suite and correction regressions. Explicit aliases must pass reviewed-policy tests.
2. **Item identity:** same kind and exact instance IDs in V1 transfers, drops, NPC inventory, equipped refs and saves; preserve the six named V1 conflict kinds plus native arrow types, stone and rare bow/sword. Under/future/shield display must not advertise unsupported functionality.
3. **Combat:** V1 melee phase/arc and ranged recovery/reload/consumption; V1 stamina/Vigor, critical, maintenance; prevent ranged ammo double-spend; validate deterministic NPC matching and existing defense order. No typed damage, resist layers, donor durability/breakage, parry or grip occupancy migration.
4. **Armor:** `resolveEquipmentModifiers` remains authoritative for worn scalar reduction, after held defense. Verify movement/recovery/sprint multipliers, quality caps, 044 legacy `arms` migration and NPC/player parity; no extra protection on underlayers.
5. **Availability:** exact source table allowlist + finite stock, no automatic `active` admission, no unique duplication; V1-native future exceptions unchanged. `createAcquiredInstance` and all owner/save/drop paths covered before enablement.
6. **UI:** three-panel hybrid rows select without gameplay; actions still in details; owned-instance equipment preview based on live slots only, no V3 parry/typed-stat banners or donor-only actions.
7. **Performance:** focused unit/integration tests for inert catalogue/isolated definitions and save semantics. Use targeted runtime/visual smoke for newly instantiated GLBs, NPCs or bulk merchant rows; profile frame time/draw calls only when workload or rendering cost materially changes. **No repeated full GPU/world baseline for isolated catalogue edits**, and no performance-affecting merge while A/B/C reference measurements are ongoing.
8. **Publication / rollback:** each PR documents files, validation evidence, migration/change policy, feature availability and rollback. If new kinds may exist in saved worlds, rollback must remain able to load or intentionally reject those saves under the approved versioned-save policy; never silently coerce them to unrelated V1 kinds.
