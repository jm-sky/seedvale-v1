# System Critical Review Matrix

**Status:** populated inventory · **Created:** 2026-11-03 · **Evidence snapshot:** 2026-11-03

This register tracks **system-level critical review coverage**, not individual review reports. It identifies reviewable system boundaries and gates; it does not perform the reviews. Historical and narrow reports do not confer current full-system coverage.

## Review methodology

- Reviews are independent and critical: assess correctness, architecture, determinism, lifecycle, persistence, performance, regression risks and alignment with the V1 Revival direction as relevant to scope.
- Reviewers may challenge fundamental architectural decisions and propose alternative architectures, provided they explain evidence, trade-offs, migration cost and risks. Findings and proposals are **not implementation approval**.
- GPT (ChatGPT) is expected to perform most reviews; Anthropic (e.g. Claude Opus) may independently review selected areas. Record each provider's coverage separately.
- One capable agent may run the review end-to-end. For larger systems, a strong coordinator may delegate bounded evidence gathering or targeted investigations to smaller sessions, while retaining responsibility for the final critical assessment.
- Match model capability and reasoning effort to system complexity; smaller, well-bounded systems can be reviewed by a smaller model.
- Review readiness must reflect **actual implementation and active Revival work**. Mark systems awaiting substantial planned changes as waiting, or split out mature subareas as partial. An early architectural review may be commissioned explicitly to inform a pending decision.
- Prefer current code and tests over documentation; distinguish verified behaviour, documented intent and outstanding runtime/visual/performance checks.
- Link each review report and relevant Revival blockers. A historical, narrow or superseded review does not automatically count as current system-level coverage.

## Readiness

- `ready` — major relevant changes finished; suitable for a system-level review.
- `partial` — some subareas are reviewable; scope and exclusions must be stated.
- `waiting` — significant Revival work remains; record the blocker.
- `unassessed` — requires inventory and verification.

Review cells should identify the date, model, report link and coverage/validity where available; otherwise use `not verified`.

## Integration boundaries: geography ↔ hydrology ↔ settlements ↔ roads

1. **Terrain/continent** ([continentMask](../../src/terrain/continentMask.ts), [chunkHeightmap](../../src/terrain/chunkHeightmap.ts)) provides a deterministic finite land base; **global hydrology** ([worldHydrology](../../src/terrain/worldHydrology.ts)) corrects elevations and exposes river/lake/land-water semantics. Neither water rendering nor per-chunk tile meshes may become the source of hydrological truth.
2. **Selected settlement sites and identity** ([settlementLayout](../../src/settlement/settlementLayout.ts)) are consumed by **VillagePlan** ([villagePlanner](../../src/settlement/villagePlanner.ts)); water/shore clearance, cemetery reservation, house/yards, bay slots and route entrances must share the same accepted footprints. Caves, fauna and world locations consume site/land validity too.
3. **Road graph and crossings** ([roadNetwork](../../src/settlement/roadNetwork.ts), [roadRiverCrossing](../../src/settlement/roadRiverCrossing.ts), [villageLanes](../../src/settlement/villageLanes.ts)) depend on selected settlement sites, hydrology, wetness and real building obstacles. Q80's hydrology finalization precedes Q61–Q64's final route shaping; Q97 checks bridge axis alignment. A road's visual ribbon is not proof that the graph connects or that an NPC can traverse the crossing.
4. **Cross-domain validation gate:** after Q80 and Q61–Q64/Q97, compare both seeds' hydrology, road and access censuses, cave count/archetypes, stable settlement/object identities, worldgen cache epochs, save/rebuild behaviour, and author-viewed river/settlement/road cases. These are **review prerequisites/evidence**, not results claimed by this file.
